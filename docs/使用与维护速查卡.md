> 这是**上线之后**的运维手册：怎么开号、怎么看日志、怎么调并发、怎么备份、怎么搬到新服务器、出问题怎么查。
> **第一次部署**请看 [小白部署教程](小白部署教程.md)；**从 v13 升级**看 [v14部署说明](v14部署说明.md)。

## 0. 一分钟看懂这套东西

```
 手机 / 电脑浏览器
        │  http://<你的服务器IP>:5000
        ▼
 ┌────────────────────┐        ┌────────────────────┐
 │  chaoxing-web      │        │  chaoxing-worker   │
 │  Flask 面板        │        │  真正跑刷课的进程   │
 │  · 登录 / 成员管理  │        │  · 认领任务         │
 │  · 建任务 / 看日志  │        │  · 起 main.py 子进程│
 └─────────┬──────────┘        └─────────┬──────────┘
           └───────────┬──────────────────┘
                       ▼
            宿主机目录 /opt/chaoxing/data
            ├── chaoxing.db     （任务、日志、成员）
            ├── configs/        （每个任务一份 .ini，含学习通账号密码）
            ├── logs/           （每个任务的完整文本日志）
            ├── cookies.txt     （登录态）
            └── secret.key      （面板登录令牌密钥）
```

**三句话记住它：**

1. **关掉浏览器不影响刷课** —— 任务跑在服务器上。
2. **数据全在 `/opt/chaoxing/data/`** —— 不在容器里，删容器不丢数据。
3. **同时能刷几个账号 = 所有 worker 容器的 `MAX_CONCURRENT` 之和** —— 登录、开号人数不受限。

## 1. 服务器上的目录（数据在哪）

```
/opt/chaoxing/                 ← 项目目录
├── Dockerfile  docker-compose.yml
├── web_panel.py  worker.py  db.py  auth.py  main.py
├── api/  templates/  resource/  tests/  docs/
└── data/                      ← ★ 唯一需要备份的东西
    ├── chaoxing.db            ← 数据库（任务/日志/成员/课程缓存）
    ├── chaoxing.db-wal         (SQLite WAL，一起备份)
    ├── configs/task_*.ini     ← 每个任务的配置（★ 明文含学习通手机号+密码）
    ├── logs/task_*.log        ← 每个任务的完整文本日志
    ├── cookies.txt            ← 学习通登录态
    └── secret.key             ← 面板令牌密钥（删了 = 所有人重新登录）
```

| 文件 | 能删吗 | 说明 |
|---|---|---|
| `data/chaoxing.db` | ❌ 不能 | 删了任务历史和成员全没 |
| `data/configs/task_*.ini` | ❌ 不能 | 删了待跑/在跑的任务会失效 |
| `data/secret.key` | ⚠️ 尽量别删 | 删了所有人要重新登录（数据不丢） |
| `data/cookies.txt` | ✅ 可以 | 删了下次刷课时自动重新登录 |
| `data/logs/*.log` | ✅ 可以 | 只是文本日志，定期清理省磁盘 |

> ⚠️ **`data/` 里有学习通明文密码，绝不要分享或上传到任何地方。**

## 2. 常用命令速查

> 全部在服务器上执行。下面统一用镜像名 `chaoxing-web:v14`。

### 看状态

```bash
docker ps --filter name=chaoxing --format "table {{.Names}}\t{{.Image}}\t{{.Status}}"
```

期望两行 `Up`：`chaoxing-web`、`chaoxing-worker`。

### 看日志

```bash
docker logs --tail 50 chaoxing-worker        # Worker 日志（认领任务 / 报错）
```
```bash
docker logs --tail 30 chaoxing-web           # 面板日志（API 报错）
```
```bash
tail -f /opt/chaoxing/data/logs/task_1.log   # 某个任务的完整文本日志（Ctrl+C 退出）
```

### 启 / 停 / 重启

```bash
docker restart chaoxing-web chaoxing-worker
```
```bash
docker stop chaoxing-web chaoxing-worker && docker start chaoxing-web chaoxing-worker
```

> 重启 worker **不会丢任务**：在跑的任务会被中断，worker 起来后按 `AUTO_RESUME=true` 自动续跑
> （脚本是幂等的，会跳过已完成的任务点）。

### 改并发（同时刷课人数）

把下面的 `N` 换成你要的数字，整条执行：

```bash
docker rm -f chaoxing-worker && docker run -d --name chaoxing-worker -v /opt/chaoxing/data:/app/data -e AUTO_RESUME=true -e MAX_CONCURRENT=N --restart unless-stopped chaoxing-web:v14 python3 worker.py
```

确认：

```bash
docker logs --tail 3 chaoxing-worker
```

期望：`[Worker] 已启动 (PID: 1)，最多同时执行 N 个任务...`

### 改端口（例如 5000 → 8080）

```bash
docker rm -f chaoxing-web && docker run -d --name chaoxing-web -p 8080:8080 -v /opt/chaoxing/data:/app/data -e PORT=8080 -e AUTO_RESUME=true --restart unless-stopped chaoxing-web:v14 python3 web_panel.py
```

> 改了端口记得云控制台**安全组/防火墙**也放行，并把新网址重新发给成员。

### 进容器看看

```bash
docker exec -it chaoxing-web bash
```

## 3. 环境变量总表

| 变量 | 默认 | 用在哪 | 说明 |
|---|---|---|---|
| `PORT` | 5000 | web | 监听端口 |
| `HOST` | 0.0.0.0 | web | 监听地址 |
| `CHAOXING_DB` | `data/chaoxing.db` | 两者 | 数据库路径 |
| `CHAOXING_COOKIES` | `/app/data/cookies.txt` | worker | Cookie 路径（**必须在共享卷内**） |
| `AUTO_RESUME` | false | worker | 启动时续跑被中断的任务（建议开） |
| `MAX_CONCURRENT` | 1 | worker | 容器内并行任务数（决定同时刷几个） |
| `PANEL_SECRET` | 自动生成 | web | 登录令牌签名密钥；不设则写入 `data/secret.key` |
| `PANEL_ADMIN_RESET` | — | web | 设 `1` 时启动会把管理员密码重置为 `admin123456`（救急用） |

## 4. 账号与成员管理

**都在网页上做：用管理员号登录 → 设置 → 成员管理。**

| 操作 | 怎么做 |
|---|---|
| 加一个成员 | 填「用户名 + 初始密码」→ 添加成员 |
| 批量加 | 每行一个「用户名 密码」→ 批量添加 |
| 改密码 | 成员列表里点「改密」 |
| 停用 / 启用 | 成员列表里点「停用」/「启用」（停用后无法登录） |
| 删除 | 成员列表里点「删除」 |
| 改自己的密码 | 设置 → 修改密码 |

**规则：**

- **一人一个面板账号 ↔ 一个学习通账号**（成员登录后自己绑定）。
- 成员之间**互相看不到**任务、日志、绑定的号（越权请求后端一律拒绝）。
- **同一个账号一次只能刷一门课**，刷完再去选下一门。

### 忘记管理员密码

```bash
docker rm -f chaoxing-web && docker run -d --name chaoxing-web -p 5000:5000 -v /opt/chaoxing/data:/app/data -e AUTO_RESUME=true -e PANEL_ADMIN_RESET=1 --restart unless-stopped chaoxing-web:v14 python3 web_panel.py
```

启动后管理员密码变为 `admin123456`，**登录后立刻改掉**。
（该开关只在启动那一次生效，下次不带它启动就恢复正常。）

可调项：
- `PANEL_ADMIN_USER=名字` —— 重置哪个管理员（默认 `admin`）。**这个名字不存在时会直接创建一个**，所以哪怕你当初起的管理员名不是 `admin`，也不会被锁在门外。
- `PANEL_ADMIN_PASSWORD=新密码` —— 重置成什么（默认 `admin123456`）。

完整示例（管理员叫 `xiaoming`，重置成 `mynewpass`）：

```bash
docker rm -f chaoxing-web && docker run -d --name chaoxing-web -p 5000:5000 -v /opt/chaoxing/data:/app/data -e AUTO_RESUME=true -e PANEL_ADMIN_RESET=1 -e PANEL_ADMIN_USER=xiaoming -e PANEL_ADMIN_PASSWORD=mynewpass --restart unless-stopped chaoxing-web:v14 python3 web_panel.py
```

> 重置完成后，**下次启动记得去掉这几个变量**，否则每次重启都会把密码重置回去。

### 想让所有人都重新登录一次

```bash
rm -f /opt/chaoxing/data/secret.key && docker restart chaoxing-web chaoxing-worker
```

> 数据不丢，只是所有人需要重新登录。

## 7. 并发、内存与超星风控

### 并发怎么定

| 服务器内存 | 建议 `MAX_CONCURRENT` |
|---|---|
| 2 GB | **3**（稳妥）；最多 5，且需开 swap |
| 4 GB | 6 ~ 8 |
| 8 GB+ | 10 以上 |

参考：**单个任务约 100~150 MB**（`ddddocr` 验证码识别是「用到才加载」，平时不占）。
一旦某个任务撞上验证码，那个进程会临时再涨 200~300 MB —— 这是真正的内存尖峰。

### 内存不够怎么办

```bash
free -m
```
```bash
docker stats --no-stream --format "table {{.Name}}\t{{.MemUsage}}\t{{.MemPerc}}"
```

`Swap` 那行 `used` 涨到 1G 以上 → 内存吃紧，把 `MAX_CONCURRENT` 降下来。

开 2G swap（一次性）：

```bash
fallocate -l 2G /swapfile && chmod 600 /swapfile && mkswap /swapfile && swapon /swapfile
```
```bash
echo '/swapfile none swap sw 0 0' >> /etc/fstab
```

### 403 / 被风控

**现象**：日志里大量 `403`，或者**换个账号也 403**。

**原因**：并发太高、请求太密，超星把**服务器 IP** 拉黑了（跟内存无关）。

**处理顺序**：

1. 降并发（`MAX_CONCURRENT` 改 3~5），观察一天
2. 还不行 → 换服务器公网 IP（云控制台换弹性公网 IP，或换机器）
3. 长期来看：**别贪并发**，3~5 个是安全区

## 8. 备份、恢复与迁移

### 备份（30 秒）

```bash
cd /opt/chaoxing && tar czf ~/cx-data-$(date +%m%d).tar.gz data && ls -lh ~/cx-data-*.tar.gz
```

得到 `~/cx-data-1014.tar.gz`，**这一个文件就是全部数据**（数据库 + 任务配置 + Cookie + 密钥 + 日志）。
想自动备份，加个定时任务：

```bash
(crontab -l 2>/dev/null; echo "0 4 * * * cd /opt/chaoxing && tar czf /root/cx-data-\$(date +\%m\%d).tar.gz data") | crontab -
```

### 在同一台机器上恢复

```bash
docker rm -f chaoxing-web chaoxing-worker && cd /opt/chaoxing && rm -rf data && tar xzf ~/cx-data-1014.tar.gz
```
```bash
docker run -d --name chaoxing-web -p 5000:5000 -v /opt/chaoxing/data:/app/data -e AUTO_RESUME=true --restart unless-stopped chaoxing-web:v14 python3 web_panel.py
```
```bash
docker run -d --name chaoxing-worker -v /opt/chaoxing/data:/app/data -e AUTO_RESUME=true -e MAX_CONCURRENT=3 --restart unless-stopped chaoxing-web:v14 python3 worker.py
```

### 迁移到一台新服务器

**旧服务器**：打包代码 + 数据

```bash
cd /opt/chaoxing && tar czf ~/cx-full.tar.gz data Dockerfile docker-compose.yml *.py *.sh api templates resource requirements.txt docs && ls -lh ~/cx-full.tar.gz
```

把 `~/cx-full.tar.gz` 下载到本地（Workbench「下载文件」/ FinalShell 拖出）。

**新服务器**：

1. 装 Docker：

```bash
apt update && apt install -y docker.io && systemctl enable --now docker
```

2. 上传 `cx-full.tar.gz` 到 `/opt/`，解压：

```bash
mkdir -p /opt/chaoxing && tar xzf /opt/cx-full.tar.gz -C /opt/chaoxing && cd /opt/chaoxing && ls
```

3. 构建并启动：

```bash
docker build -t chaoxing-web:v14 .
```
```bash
docker run -d --name chaoxing-web -p 5000:5000 -v /opt/chaoxing/data:/app/data -e AUTO_RESUME=true --restart unless-stopped chaoxing-web:v14 python3 web_panel.py
```
```bash
docker run -d --name chaoxing-worker -v /opt/chaoxing/data:/app/data -e AUTO_RESUME=true -e MAX_CONCURRENT=3 --restart unless-stopped chaoxing-web:v14 python3 worker.py
```

4. 云控制台**放行 5000 端口**，浏览器打开新 IP 验证。

> ⚠️ 新服务器 IP 变了，**网址要重新发给成员**；账号、密码、数据都不变。

## 9. 故障排查

| 现象 | 先查什么 |
|---|---|
| 网页打不开 | ① 用 `http://`（不是 https）② `docker ps` 两个容器是否 Up ③ 云安全组放行 5000 了吗 |
| 容器起不来 | `docker logs --tail 30 chaoxing-web`（看报错） |
| 任务一直「排队中」 | worker 在跑吗？`docker ps` + `docker logs --tail 20 chaoxing-worker`；并发满了也会排队 |
| 「运行中」但没进度 | `tail -30 /opt/chaoxing/data/logs/task_N.log`；常见是撞上验证码或课程需解锁 |
| 暂停/停止按钮点不动 | 无任务时是灰的（正常），有任务才能点 |
| 所有人都被登出 | `data/secret.key` 丢了或被删，重新登录即可 |
| 登录学习通失败 | 先在手机 App 登录一次（异地登录风控）；提示冻结等 15 分钟 |
| 磁盘满了 | `du -sh /opt/chaoxing/data`，清老日志：`find /opt/chaoxing/data/logs -name 'task_*.log' -mtime +30 -delete` |
| 服务器重启后没起来 | `systemctl is-enabled docker` 应为 `enabled`；容器 restart 策略应为 `unless-stopped` |

## 10. 安全建议

1. **限制访问来源**（推荐）
   云控制台 → 安全组/防火墙 → 5000 端口规则 → 把「授权对象」从 `0.0.0.0/0` 改成一个具体网段或你自己的 IP
   （缺点是换网络就要改）。**注意：这只能挡网络层，面板本身靠登录鉴权。**
2. **给每个成员单独开号**，不要多人共用同一个账号。
3. **数据目录收紧权限**：

```bash
chmod 700 /opt/chaoxing/data
```

4. **`data/` 绝对不要提交到 Git、不要发给别人**（里面有学习通明文密码）。
5. 不用时可以停掉：

```bash
docker stop chaoxing-web chaoxing-worker
```

## 11. 升级代码 / 回退旧版

### 升级（保留旧镜像便于回退）

```bash
cd /opt/chaoxing && tar czf ~/cx-data-$(date +%m%d).tar.gz data      # ① 先备份
```
```bash
unzip -o chaoxing-vXX.zip                                            # ② 覆盖代码
```
```bash
docker build -t chaoxing-web:XX .                                    # ③ 用新标签构建
```
```bash
docker rm -f chaoxing-web chaoxing-worker                            # ④ 删旧容器
```
```bash
docker run -d --name chaoxing-web -p 5000:5000 -v /opt/chaoxing/data:/app/data -e AUTO_RESUME=true --restart unless-stopped chaoxing-web:XX python3 web_panel.py
```
```bash
docker run -d --name chaoxing-worker -v /opt/chaoxing/data:/app/data -e AUTO_RESUME=true -e MAX_CONCURRENT=3 --restart unless-stopped chaoxing-web:XX python3 worker.py
```

### 回退

容器跑的是**镜像里**的代码，只要旧镜像还在，换个标签重跑就行：

```bash
docker images | grep chaoxing                                        # 看有哪些版本
```
```bash
docker rm -f chaoxing-web chaoxing-worker
```
```bash
docker run -d --name chaoxing-web -p 5000:5000 -v /opt/chaoxing/data:/app/data -e AUTO_RESUME=true --restart unless-stopped chaoxing-web:旧标签 python3 web_panel.py
```
```bash
docker run -d --name chaoxing-worker -v /opt/chaoxing/data:/app/data -e AUTO_RESUME=true -e MAX_CONCURRENT=3 --restart unless-stopped chaoxing-web:旧标签 python3 worker.py
```

> ⚠️ 这就是为什么**构建要用带版本号的标签**（如 `:v14`），而不要一直用 `:latest` ——
> 用 `latest` 会把旧镜像覆盖掉，想回退就没得退了。
