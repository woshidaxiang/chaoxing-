# 架构说明（技术参考）

> 面向想读懂代码/改代码的人。**只想用起来的**看 [小白部署教程](小白部署教程.md) 就够了。

## 整体设计

本项目在 [Samueli924/chaoxing](https://github.com/Samueli924/chaoxing) 命令行脚本之上，
增加了一套「Web 面板 + 独立 Worker + SQLite 持久化 + 多用户登录」的部署方案。

```
┌─────────────────────────────────────────────────────────────┐
│                         云服务器                              │
│                                                             │
│  ┌──────────────────┐        ┌──────────────────────────┐   │
│  │  chaoxing-web    │        │   chaoxing-worker        │   │
│  │  (Flask 容器)     │        │   (任务执行容器)          │   │
│  │                  │        │                          │   │
│  │  · 网页界面       │        │  · 轮询数据库认领任务      │   │
│  │  · 登录/成员管理   │        │  · 启动 main.py 子进程    │   │
│  │  · 绑定学习通账号  │        │  · 实时日志写库           │   │
│  │  · 创建任务入队   │        │  · 心跳上报               │   │
│  │  · 状态/日志/SSE  │        │  · 暂停/停止响应          │   │
│  └────────┬─────────┘        └────────────┬─────────────┘   │
│           │                               │                 │
│           └───────────┬───────────────────┘                 │
│                       ▼                                     │
│            ┌─────────────────────┐                          │
│            │  data/chaoxing.db   │  ← SQLite（WAL 模式）     │
│            │  data/configs/      │  ← 任务配置               │
│            │  data/logs/         │  ← 日志文本备份           │
│            │  data/cookies.txt   │  ← 学习通登录态（按账号隔离）│
│            │  data/secret.key    │  ← 面板令牌签名密钥        │
│            └─────────────────────┘                          │
└─────────────────────────────────────────────────────────────┘
```

## 为什么这样设计？

| 问题 | 解决方式 |
| --- | --- |
| 关掉手机/浏览器后任务要能继续 | 任务在服务器 Worker 里执行，与浏览器无关 |
| 重新打开网页要能看到之前的日志和进度 | 状态和日志持久化到 SQLite |
| Web 服务重启/崩溃不能影响正在跑的任务 | Web 和 Worker 是**独立进程/容器** |
| 怎么知道任务是不是真的在跑 | Worker 定期更新 `heartbeat`；Web 用「状态=running 且心跳新鲜」判断存活 |
| 服务器重启后任务怎么办 | Worker 启动时把心跳超时的任务标记为 interrupted；`AUTO_RESUME=true` 时自动重新排队续跑（脚本幂等，会跳过已完成任务点） |
| 多人同时用怎么互不干扰 | 每个面板账号（`users`）绑定一个学习通号（`accounts`），任务与日志按 `owner` 隔离；越权请求后端拒绝 |
| 多个账号同时跑会不会互相覆盖 Cookie | Cookie 按账号分文件 + 每线程独立 Session（`api/base.py` 的 `_tls`、`api/cookies.py`） |
| 一个容器能同时跑几个 | `MAX_CONCURRENT`（worker 容器内并行任务数），超出部分排队 |

## 数据表

| 表 | 用途 |
| --- | --- |
| `tasks` | 任务：状态 / 学习通账号 / 课程 / 倍速 / 归属 owner / PID / 心跳 / 时间 |
| `logs` | 任务日志（`task_id + id` 建索引，支持增量拉取与裁剪） |
| `courses_cache` | 课程列表缓存（避免每次都拉取） |
| `users` | **面板账号**：用户名 / 密码哈希 / 角色(admin,user) / 是否停用 / 最后登录 |
| `accounts` | **面板账号 ↔ 学习通账号**绑定关系（含加密存储的学习通密码） |
| `invite_codes`、`user_courses` | 预留给邀请码 / 逐门课授权的表，**当前版本未启用** |

**tasks 关键字段**

| 字段 | 说明 |
| --- | --- |
| id / owner | 任务 ID / 归属的面板用户名（隔离用） |
| status | pending / running / finished / error / stopped / interrupted |
| username / courses | 学习通账号 / 课程 ID 列表 |
| speed / jobs | 倍速 / 课程内并发 |
| config_path | 生成的配置文件路径（`data/configs/task_N.ini`） |
| worker_pid / script_pid | Worker 进程 PID / main.py 子进程 PID |
| stop_requested / paused | 停止请求 / 是否暂停（SIGSTOP） |
| heartbeat | 心跳时间戳（判断存活） |
| start_time / end_time / exit_code | 起止时间 / 退出码 |

## 鉴权与隔离

- **面板登录**：`auth.py` 生成 HMAC-SHA256 签名的无状态令牌，放在 **HttpOnly Cookie**；
  密钥来自环境变量 `PANEL_SECRET`，未设置时自动生成并保存在 `data/secret.key`。
- 所有业务接口都先过 `_check_login()`，拿到当前用户；**任务/日志/账号一律按 owner 过滤**。
- **首次使用**：库里没有任何账号时，`/api/setup/status` 返回「需要初始化」，前端显示「创建管理员」；
  一旦有账号，该入口自动关闭（只能登录）。
- **管理员**：可管理成员；不能停用/删除自己。

## 关键流程

### 面板登录

1. 前端 POST `/api/auth/login`（用户名 + 密码）
2. 后端校验 `users` 表里的密码哈希 → 签发令牌 → 写 HttpOnly Cookie
3. 前端 GET `/api/auth/me` 拿当前身份（决定是否显示「成员管理」）

### 绑定学习通账号

1. 前端 POST `/api/account/bind`（学习通手机号 + 密码）
2. 后端用该账号登录超星 → 成功则写入 `accounts`（密码加密存储）并在该账号的 Cookie 文件里保存登录态
3. 前端 GET `/api/account` 显示绑定状态

### 启动任务

1. 前端 POST `/api/start`（课程、倍速等）
2. Web 生成 `configs/task_N.ini`，插入一条 `status=pending` 的任务（带 owner）
3. Worker 轮询 `claim_next_pending()`（`BEGIN IMMEDIATE` 原子认领，有空位就领）
4. Worker 启动 `python main.py -c config.ini`，把 `script_pid` 写库
5. 逐行读取输出 → 批量写 `logs` 表；定期更新 `heartbeat`
6. 结束 → 更新 status / exit_code / end_time

### 暂停 / 继续 / 停止

- **暂停**：`POST /api/pause` → Worker 对子进程发 `SIGSTOP`（真挂起，不丢进度）；继续发 `SIGCONT`
- **停止**：`POST /api/stop` → 写 `stop_requested=1` 并尝试直接 kill `script_pid`；
  Worker 也会周期性检查该标记并终止子进程

### 页面加载恢复

1. 前端 GET `/api/current` → 最近任务 + `is_alive`（基于心跳）
2. 前端 GET `/api/logs?after=0` 拉历史日志
3. 打开 SSE `/api/logs/stream` 接收增量日志；前端另有定时兜底轮询保证按钮状态同步

## 部署形态

### Docker（推荐）

- `docker-compose.yml` 定义两个服务，**共用同一镜像**（如 `chaoxing-web:v14`）
- 共用宿主目录 `./data`（数据持久化）
- `restart: unless-stopped` 保证崩溃自动拉起
- worker 用 `command: ["python3", "worker.py"]` 覆盖镜像的默认 `CMD`

### 非 Docker

- `start.sh` 用 `nohup` 分别拉起 `web_panel.py` 和 `worker.py`
- PID 写入 `data/*.pid`，`stop.sh` 负责停止

## 环境变量

| 变量 | 默认 | 作用域 | 说明 |
| --- | --- | --- | --- |
| `PORT` | 5000 | web | 监听端口 |
| `HOST` | 0.0.0.0 | web | 监听地址 |
| `CHAOXING_DB` | `data/chaoxing.db` | 两者 | 数据库路径 |
| `CHAOXING_COOKIES` | `/app/data/cookies.txt` | worker | Cookie 路径（必须在共享卷内） |
| `AUTO_RESUME` | false | worker | 启动时自动续跑被中断的任务 |
| `MAX_CONCURRENT` | 1 | worker | 容器内并行任务数 |
| `MAX_LOGS_PER_TASK` | 1500 | 两者 | 单任务日志保留条数（超出自动裁剪） |
| `PANEL_SECRET` | 自动生成 | web | 令牌签名密钥 |
| `PANEL_ADMIN_RESET` | — | web | 设为 1 时启动把管理员密码重置为 `admin123456` |

## 目录职责

| 路径 | 说明 |
| --- | --- |
| `web_panel.py` | Flask 后端：登录、成员管理、账号绑定、任务、日志、暂停/停止 |
| `auth.py` | 令牌签发与校验（HMAC-SHA256，无状态） |
| `worker.py` | 任务 Worker：认领、执行、日志、心跳、暂停监控、并行调度 |
| `db.py` | SQLite 层：建表 + 全部读写 |
| `main.py` | 上游刷课主程序（命令行入口） |
| `templates/index.html` | 前端（原生 JS，无框架，含登录页/控制面板/成员管理） |
| `api/` | 上游 API 模块（请求、题库、验证码、字体解码等） |
| `resource/` | 字体映射表（字体反爬解码用） |
| `tests/` | 回归测试（96 项） |
