# v13 修复说明 —— 并发刷课「秒过/空页面」问题

## 一、问题现象

- 点开始刷课，**几秒内就显示「全部完成」**，但视频根本没刷
- 日志里刷屏：
  ```
  api.base:study_emptypage:1597 - 空页面任务完成 -> 1.2 第二课时
  api.base:get_job_list:699 - 章节任务点读取成功...
  __main__:worker_thread:408 - Task success: ...
  ```
- **每个章节 1~3 秒就"完成"**，明显不正常

## 二、排查过程（结论）

逐步排除后确认：

| 排查项 | 结果 |
|--------|------|
| 账号能不能登录 | ✅ 正常，能拿到真实姓名 |
| Cookie 有没有丢 | ✅ 正常 |
| 课程/章节能不能读到 | ✅ 正常，46 个章节 |
| 单个章节能不能解析出视频 | ✅ **单线程测试完全正常**（返回 `video 雕塑1(2).mp4`） |
| **4 线程并发时** | ❌ **全部返回 0 个任务点** |

**决定性证据：**

```
单线程跑：  1.1 → 1 个任务点  ✅
4 线程并发：1.1 → 0，1.2 → 0，1.3 → 0，1.4 → 0  ❌
```

## 三、根本原因

**`requests.Session` 不是线程安全的。**

刷课脚本默认以 **4 个线程并发**（配置里 `jobs = 4`），但所有线程**共用同一个 Session 对象**。

多线程同时发请求时：

1. 线程 A 发请求，超星返回响应并带 `Set-Cookie`
2. 线程 B 同时也在发请求，**它的响应 cookie 覆盖了 A 的**
3. 结果：会话被污染 → 超星返回「未登录」的页面
4. 那个页面**没有 `mArg` 数据** → 解析出 0 个任务点
5. 脚本认为「这章节没有任务点」→ 判定空页面 → 标记成功 → 秒过

**所以单线程测试一切正常，一开并发就全崩。**

## 四、修复内容（v13）

### 1. 每个线程使用独立的 session

`api/base.py` 的 `SessionManager` 重写：

- 用 `threading.local()` 保存**每线程自己的 `requests.Session`**
- 每个线程有独立的 cookie jar，互不干扰
- 所有线程通过 `_shared_cookies` 共享同一份登录态（登录后同步）

```python
_tls = threading.local()

@classmethod
def get_session(cls) -> requests.Session:
    """返回「当前线程」专属的 session（线程安全）。"""
    sess = getattr(cls._tls, "session", None)
    if sess is None:
        sess = cls._build_session()
        sess.cookies = sess.cookies.__class__()   # 独立 cookie jar
        sess.cookies.update(use_cookies())
        ...
        cls._tls.session = sess
    return sess
```

### 2. 登录后刷新当前线程 session

登录成功后调用 `SessionManager.reset_thread_session()`，
丢弃旧的无登录态 session，重建带 cookie 的 session。

### 3. Cookie 路径改到共享卷（附带修复）

`api/config.py`：

```python
# 旧：COOKIES_PATH = "cookies.txt"          ← 相对路径，落在 /app，容器重建就丢
# 新：绝对路径，落在挂载卷 /app/data，容器重建不丢
COOKIES_PATH = os.environ.get("CHAOXING_COOKIES", "/app/data/cookies.txt")
```

`Dockerfile` 同步加了 `ENV CHAOXING_COOKIES=/app/data/cookies.txt`。
