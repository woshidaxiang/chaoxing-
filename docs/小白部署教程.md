## 第 0 章 先搞懂：这东西是怎么跑的

```
   你的手机 / 电脑                      云服务器（24 小时开机）
  ┌──────────────┐                  ┌────────────────────────────────┐
  │ 浏览器打开网页 │ ──────上网─────▶ │ ① chaoxing-web（网页面板）      │
  │              │                  │   登录、开号、选课、看日志        │
  │ 看完就关掉也行 │                  │                                │
  └──────────────┘                  │ ② chaoxing-worker（真正干活的）  │
                                    │   独立进程，跟网页没关系          │
                                    │   · 认领任务 → 跑刷课脚本        │
                                    │   · 写日志、发心跳、响应暂停      │
                                    │                                │
                                    │ ③ data/chaoxing.db（SQLite）    │
                                    │   任务、日志、账号全都存在磁盘上   │
                                    └────────────────────────────────┘
```

**三个关键点：**

| 你可能担心的 | 实际是怎么做的 |
|------|------|
| 要一直挂着手机/电脑吗？ | **不用**。任务跑在服务器的 Worker 里，你关掉浏览器、手机关机都不影响 |
| 关掉网页后进度会丢吗？ | **不会**。状态和日志都写进 SQLite 数据库，下次打开自动恢复 |
| 网页崩了任务会停吗？ | **不会**。Web 和 Worker 是两个独立容器，重启网页不影响正在跑的任务 |

## 第 1 章 准备：服务器与端口

### 1.1 你会用到的东西

- 一台云服务器（阿里云 / 腾讯云 / 甲骨文云 都行，见 1.2）
- 服务器的**公网 IP**、**root 密码**（买的时候设的）
- 大约 30 分钟

### 1.2 服务器怎么选

| 项目 | 建议 | 说明 |
|------|------|------|
| 系统 | **Ubuntu 22.04**（64 位） | 教程最多，Docker 支持最好 |
| CPU | 2 核 | 够用 |
| **内存** | **建议 2GB 起步，最好 4GB** | ★ **这是真正的瓶颈**，见下 |
| 硬盘 | 40GB | 镜像 + 依赖大约占 5~6GB |
| 带宽 | 3~5 Mbps | 只是看网页，够用 |
| 地域 | 离你近的 | 延迟低一点 |

> ### ★ 为什么内存最重要
>
> 每开一个「同时刷课的任务」，服务器上就会多一个 Python 进程，**大约吃 100~150MB 内存**
> （如果遇到验证码要识别，那一下会涨到 300~400MB）。
>
> 也就是说：**同时刷 5 个人 ≈ 0.7GB，10 个人 ≈ 1.4GB**。
>
> - 1GB 内存的机器：只能同时跑 1~2 个
> - 2GB：大概 3~5 个
> - 4GB：10 个比较稳
>
> 内存不够时，Linux 会**直接杀掉进程** → 任务中断（会自动续跑，但会来回折腾）。
> 实在不想加内存，可以按 [6.5](#65-可选加-swap-和-调整并发数) 开 swap 顶一顶。

### 1.3 买服务器（以腾讯云轻量为例，阿里云同理）

1. 打开腾讯云轻量应用服务器页面 → 「立即购买」
2. 地域选离你近的（广州 / 上海 / 北京）
3. 镜像选 **Ubuntu Server 22.04 LTS**
4. 规格选 **2核2G**（或更高）
5. 买 1 个月先试
6. 付款后进控制台 → 记下**公网 IP**，并确认你设了 root 密码（没有就重置一次）

### 1.4 ★ 开放 5000 端口（不做手机连不上）

这一步是新手最容易漏的，一定要做：

- **腾讯云 / 阿里云「轻量应用服务器」**：控制台 → 你的服务器 → **「防火墙」** 标签 → 「添加规则」→
  协议 **TCP**、端口 **5000**、来源 `0.0.0.0/0` → 确定
- **阿里云「ECS 云服务器」**：控制台 → 实例 → **「安全组」** → 配置规则 → 入方向 → 添加 →
  自定义 TCP、端口范围 `5000/5000`、授权对象 `0.0.0.0/0` → 保存

> 想更安全：把「来源」填成你自己的 IP（手机流量换 IP 后要重新改，麻烦）。
> 反正**面板本身有登录密码**，先 `0.0.0.0/0` 也能用。

## 第 2 章 连上服务器

### 2.1 方式 A：网页终端（最简单，推荐）

- **阿里云**：控制台 → 实例 → 「远程连接」→ **Workbench**
- **腾讯云**：控制台 → 服务器 → 「登录」→ 输入密码

浏览器里会出现一个黑色终端，出现 `root@xxx:~#` 就说明连上了。

### 2.2 方式 B：电脑软件 / 手机 App

- 电脑：**FinalShell**（还能顺便传文件）、Xshell、MobaXterm
- 手机：**Termius**、**JuiceSSH**

连接信息：主机 = 公网 IP，用户名 = `root`，密码 = 你设的。

### 2.3 ★ 粘贴命令的三个坑（很重要）

1. **一次只贴一条命令**，别一次贴一大段。
2. 网页终端对**单行长度有限制**（大约 500 字符），太长会被截断 → 所以本教程的命令都很短。
3. 多行内容（比如把几行一起粘）**可能被吞掉换行符** → 遇到"看起来粘进去了但报错"，
   就**一行一行贴**。

> 后面所有命令，**在终端里粘贴 + 回车**即可。

## 第 3 章 安装 Docker

### 3.1 三条命令

```bash
apt update -y
```

```bash
apt install -y unzip curl
```

```bash
curl -fsSL https://get.docker.com | bash -s docker --mirror Aliyun
```

最后验证：

```bash
docker --version
```

看到 `Docker version 2x.x.x` 就成功了。

### 3.2 如果第 3 条失败（国内网络常见）

报错长这样：`curl: (35) OpenSSL SSL_connect: Connection reset by peer`
→ 换成从系统源装（版本旧一点但完全够用）：

```bash
apt install -y docker.io
```

再不行就把系统源换阿里云再来一次：

```bash
sed -i 's|archive.ubuntu.com|mirrors.aliyun.com|g; s|security.ubuntu.com|mirrors.aliyun.com|g' /etc/apt/sources.list && apt update -y && apt install -y docker.io
```

### 3.3 设置开机自启 + 国内镜像加速

```bash
systemctl enable docker --now
```

```bash
mkdir -p /etc/docker
```

```bash
printf '{\n  "registry-mirrors": ["https://docker.m.daocloud.io", "https://docker.1ms.run"]\n}\n' > /etc/docker/daemon.json
```

```bash
systemctl restart docker
```

## 第 4 章 把项目放上服务器

### 4.1 三种上传方式，选一个

**方式 A：上传压缩包（最推荐）**

1. 把项目压缩包（比如 `chaoxing-github.zip`）用网页终端/FinalShell 上传到 `/opt/chaoxing/`
2. 在终端里解压（见 4.2）

**方式 B：FinalShell 拖拽**

左边本地窗口 → 右边服务器窗口（进 `/opt/chaoxing`）→ 把文件夹里的**所有文件**拖过去。

**方式 C：从 GitHub 拉**

```bash
mkdir -p /opt/chaoxing && cd /opt/chaoxing && apt install -y git && git clone https://github.com/<你的用户名>/<仓库名>.git .
```

> ⚠️ 上传时**千万不要**把 `data/` 目录传上去（那里面是账号密码和数据库）。
> 压缩包里如果本来就没有 `data/`，就不用管这条。

### 4.2 解压

```bash
cd /opt/chaoxing && unzip -o chaoxing-github.zip
```

> 如果解压出来的文件名是乱码，说明缺 `unzip`，先跑 `apt install -y unzip`。
> 解压后如果多了一层同名文件夹，进去把里面的文件移到 `/opt/chaoxing/` 下即可。

### 4.3 自检（看数字，别肉眼看中文）

```bash
cd /opt/chaoxing && ls Dockerfile web_panel.py worker.py db.py auth.py main.py | wc -l
```

期望输出 **6**。如果是 6，说明文件齐了。

## 第 5 章 构建镜像

### 5.1 开始构建

```bash
cd /opt/chaoxing && docker build -t chaoxing-web:v14 .
```

- 第一次要下载依赖，**大约 3~8 分钟**（有国内镜像会快很多）
- 成功的标志是最后一行：`Successfully tagged chaoxing-web:v14`
- 这一步**不影响任何已运行的服务**，可以放心跑

> ### 如果"回车之后半天没反应、光标一直闪"
>
> 这是**正常的**——`docker build` 第一步要把整个目录打包发给 Docker，这个阶段不打印任何东西。
> 目录越大越久（尤其是 `data/` 里的日志）。想看得见进度就改成后台构建：
>
> ```bash
> cd /opt/chaoxing && nohup docker build -t chaoxing-web:v14 . > ~/build.log 2>&1 &
> ```
>
> 然后反复跑这条看进度：
>
> ```bash
> tail -6 ~/build.log
> ```
>
> 看到 `Successfully tagged chaoxing-web:v14` 就成了。

### 5.2 给新镜像做个体检（不碰现有服务）

```bash
docker run --rm chaoxing-web:v14 python3 -c "import web_panel, auth; print('IMAGE OK')"
```

期望输出一行：**`IMAGE OK`**。如果是别的（比如报错），请看第 10 章。

## 第 6 章 启动服务

### 6.1 启动 Web 面板

```bash
docker run -d --name chaoxing-web -p 5000:5000 -v /opt/chaoxing/data:/app/data -e AUTO_RESUME=true --restart unless-stopped chaoxing-web:v14 python3 web_panel.py
```

回车后会输出一长串容器 ID（例如 `f4528b3d44d1...`），这就是成功了。

### 6.2 启动 Worker（真正干活的）

```bash
docker run -d --name chaoxing-worker -v /opt/chaoxing/data:/app/data -e AUTO_RESUME=true -e MAX_CONCURRENT=5 --restart unless-stopped chaoxing-web:v14 python3 worker.py
```

> ⚠️ **特别注意 `python3 worker.py` 不能省**。
> 镜像默认命令是 `python3 web_panel.py`，如果你只写 `... chaoxing-web:v14 worker.py` 或 `... chaoxing-web:v14 worker`，
> 会报 `exec: "worker": executable file not found in $PATH`。**必须写全 `python3 worker.py`。**

### 6.3 确认两个容器都起来了

```bash
docker ps --format "table {{.Names}}\t{{.Image}}\t{{.Status}}"
```

期望看到 **2 行**，都是 `Up`：

```
NAMES             IMAGE              STATUS
chaoxing-worker   chaoxing-web:v14   Up ...
chaoxing-web      chaoxing-web:v14   Up ...
```

再看 Worker 日志：

```bash
docker logs --tail 5 chaoxing-worker
```

期望：

```
[Worker] 已启动 (PID: 1)，最多同时执行 5 个任务，等待任务... AUTO_RESUME=True
```

看到这一行，**服务就装好了**。

### 6.4 逐个参数解释（知道自己在敲什么）

| 片段 | 作用 |
|------|------|
| `-d` | 后台运行 |
| `--name chaoxing-web` | 给容器起名字，方便以后管理 |
| `-p 5000:5000` | 把服务器 5000 端口映射到容器 5000（左边是外面的，改它就能换端口） |
| `-v /opt/chaoxing/data:/app/data` | ★ **数据挂载**：数据库/配置/日志存在宿主机上，删容器也不丢 |
| `-e AUTO_RESUME=true` | Worker 启动时自动续跑被中断的任务 |
| `-e MAX_CONCURRENT=5` | 这个容器内最多同时跑 5 个任务（按内存调整，见第 1.2 节） |
| `--restart unless-stopped` | 服务器重启后自动拉起来 |
| `chaoxing-web:v14` | 用哪个镜像 |
| `python3 web_panel.py` / `python3 worker.py` | 这个容器里跑哪个程序 |

### 6.5 可选：加 swap 和调整并发数

**看当前内存：**

```bash
free -m
```

看 `Mem:` 行的 `available`。可用内存 ÷ 150MB ≈ 你能同时跑几个任务。

**加 2GB swap（内存紧张时的缓冲垫，溢出时用磁盘顶上）：**

```bash
fallocate -l 2G /swapfile && chmod 600 /swapfile && mkswap /swapfile && swapon /swapfile
```

```bash
echo '/swapfile none swap sw 0 0' >> /etc/fstab
```

**改并发数**（比如改成 8）：先删旧的，再用新数字起一个

```bash
docker rm -f chaoxing-worker
```

```bash
docker run -d --name chaoxing-worker -v /opt/chaoxing/data:/app/data -e AUTO_RESUME=true -e MAX_CONCURRENT=8 --restart unless-stopped chaoxing-web:v14 python3 worker.py
```

> ⚠️ 重启 Worker 会中断正在跑的任务，但 `AUTO_RESUME=true` 会自动续跑（脚本会跳过已完成的任务点）。
> ⚠️ **并发不要一味调大**：并发越高，超星风控越容易盯上你的服务器 IP（见第 10 章 Q6）。

## 第 7 章 首次使用：创建管理员 + 开号

### 7.1 ★ 第一件事：创建管理员（要抢在别人前面）

浏览器打开：

```
http://<你的服务器IP>:5000
```

第一次打开会看到 **「首次使用 · 创建管理员」** → 填你自己的用户名 + 密码（至少 6 位）→「创建并进入」。

> ### ⚠️ 为什么强调"抢在前面"
>
> 在**没有任何账号**之前，谁先打开这个网址，谁看到的就是"创建管理员"页面，**谁先提交谁就是管理员**。
> 所以：**先自己建好管理员，再去开号、发网址**。

### 7.2 开成员账号

左侧边栏（手机上在底部）→ **设置** → 找到 **「成员管理」**：

- **单个添加**：填「成员用户名」+「初始密码（≥6 位）」→ 点「添加成员」
- **批量添加**：在下面的框里，**每行一个「用户名 密码」**，例如：

  ```
  xiaoming 123456
  xiaohong abc12345
  ```

  然后点「批量添加」→ 会提示"成功 N 个"

添加完成后，下面会出现**成员列表**，每个人后面有：**改密 / 停用 / 删除**。

- **停用**：他登不上，随时可以启用回来
- **删除**：连他绑定的学习通账号一起清掉，**不可恢复**

管理员自己不能被停用或删除。

### 7.3 改密码

- 自己改：设置 → **修改密码**（要填原密码）
- 管理员帮别人改：设置 → 成员管理 → 点那个人的「改密」

## 第 8 章 成员怎么用（可以直接转发）

> **超星刷课 · 使用说明**
>
> 1. 打开 `http://<你的服务器IP>:5000`，用我给你的**用户名和密码登录**
> 2. 进「控制面板」→ **绑定超星账号**（填你自己的学习通手机号 + 密码）→ 绑定后会自动同步课程
> 3. 进「我的课程」→ 勾选一门课 → 点 **「▶ 开始刷课」**
> 4. 点完就可以**关掉浏览器**了，任务在服务器上自动跑；下次打开网址能看到进度和历史日志
> 5. ⚠️ **一次只能刷一门课**，这门刷完了，再回来选下一门
> 6. ⚠️ 刷课期间**别在手机学习通 App 里同时登录这个账号**（会互相挤下线）
> 7. 想暂停/停止：任务跑起来后，控制面板「任务状态」卡片下面有 `⏸ 暂停` 和 `⏹ 停止任务` 按钮

## 第 10 章 常见问题排查

**Q1：网页打不开？**
1. 端口放行了吗？（第 1.4 节，最常见的坑）
2. `docker ps -a --filter name=chaoxing` 看两个容器是不是都 `Up`
3. 地址要写 `http://`，**不要** `https://`，端口 `:5000` 别漏
4. 服务器上试一下：`curl -I http://127.0.0.1:5000/`，能返回 `HTTP/1.1 200` 说明服务正常，问题在网络/端口放行

**Q2：`docker run` 报 `port is already allocated`？**
说明 5000 端口被别的容器占了。先删掉旧的：`docker rm -f chaoxing-web` 再重跑。

**Q3：`docker run` 报 `The container name "/chaoxing-web" is already in use`？**
名字被占了：`docker rm -f chaoxing-web` 再重跑。

**Q4：Worker 报 `exec: "worker": executable file not found in $PATH`？**
命令写错了。**必须**是 `... chaoxing-web:v14 python3 worker.py`（`python3` 和 `worker.py` 都不能少）。

**Q5：任务一直「排队中」/「等待 Worker 认领」？**
Worker 没在跑，或者并发满了：
```bash
docker ps -a --filter name=chaoxing-worker
docker logs --tail 20 chaoxing-worker
```

**Q6：★ 日志里大量 403，或者换账号也 403？**
这是**超星按 IP 风控**（尤其是短时间内请求太密时）。这个跟内存无关，按顺序试：
1. 把 `MAX_CONCURRENT` 降到 3~5（见 6.5）
2. 用**手机流量**（不同 IP）打开 `https://mooc1.chaoxing.com` 验证一下是不是只有服务器被拦
3. 换服务器的公网 IP（阿里云/腾讯云可以在控制台换弹性 IP；轻量服务器一般不能换）
4. 或者把服务挪到**家宽电脑**上跑（住宅 IP 最不容易被拦）

**Q7：某门课视频进度不动？**
- 在手机学习通 App 里打开那门课，**把进度条拖回最开始再退出**，再回来刷（社区经验：能重置某种风控状态）
- 把题库关掉（默认就是关的）、倍速改回 1.0x

**Q8：容器一直 `Restarting`？**
```bash
docker logs --tail 30 chaoxing-web
```
多半是 `data/` 目录权限或数据库损坏。可以先把 `data/chaoxing.db` 备份走，再删掉让它重建（**会丢历史记录，但账号会重建**）。

**Q9：内存不够，任务老是被中断？**
`free -m` 看 `available`；`docker stats --no-stream` 看容器吃多少。
降 `MAX_CONCURRENT`，或者按 6.5 加 swap，或者升配服务器内存。

**Q10：忘记管理员密码了？**
删掉 web 容器，用带 `PANEL_ADMIN_RESET=1` 的命令重启，密码会被重置成 `admin123456`：
```bash
docker rm -f chaoxing-web && docker run -d --name chaoxing-web -p 5000:5000 -v /opt/chaoxing/data:/app/data -e AUTO_RESUME=true -e PANEL_ADMIN_RESET=1 --restart unless-stopped chaoxing-web:v14 python3 web_panel.py
```
登录后**立刻去设置里改密码**，下次启动把那个环境变量去掉。
（想重置成别的密码，再加 `-e PANEL_ADMIN_PASSWORD=你要的密码`）

**Q11：所有人都被"强制退出登录"了？**
`data/secret.key` 丢了（那是登录令牌的签名密钥）。重新登录一次即可，数据不丢。

**Q12：构建时卡在下载依赖？**
Dockerfile 里已经换成国内源了。如果还卡，先确认第 3.3 节的镜像加速配好了。

**Q13：面板能加多少人？**
登录和开号**不限人数**。只有"**同时开刷**"受 `MAX_CONCURRENT` 限制，超出的会排队，前面跑完自动顶上。

**Q14：任务刷完一门会自动刷下一门吗？**
不会。本项目**一次只刷一门课**（防止多课并发出错），刷完需要成员自己回来再选一门。

## 第 11 章 环境变量速查

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `PORT` | `5000` | Web 面板监听端口（改这里要同步改 `-p` 映射） |
| `HOST` | `0.0.0.0` | 监听地址，一般不用改 |
| `CHAOXING_DB` | `data/chaoxing.db` | 数据库文件路径 |
| `CHAOXING_COOKIES` | `/app/data/cookies.txt` | Cookie 存放路径（**必须在挂载卷里**） |
| `AUTO_RESUME` | `false` | Worker 启动时是否续跑被中断的任务（本教程设为 `true`） |
| `MAX_CONCURRENT` | `1` | 单个 worker 容器内最多同时跑几个任务 |
| `PANEL_SECRET` | 自动生成 | 登录令牌签名密钥；不设会自动写 `data/secret.key` |
| `PANEL_TOKEN_TTL` | `604800` | 登录有效期（秒），默认 7 天 |
| `PANEL_ADMIN_RESET` | — | 设为 `1` 时启动会把管理员密码重置为 `admin123456`（救急） |
| `PANEL_ADMIN_USER` | `admin` | 配合上面用，指定重置哪个管理员 |
| `PANEL_ADMIN_PASSWORD` | `admin123456` | 配合上面用，指定重置成什么密码 |
| `DROP_DEBUG_LOG` | `true` | 丢掉 TRACE/DEBUG 日志，避免刷屏 |
| `MAX_LOGS_PER_TASK` | `1500` | 每个任务最多保留多少条日志（超出删最旧的） |
| `PROGRESS_KEEP_INTERVAL` | `10` | 进度条日志最多每 N 秒保留一条 |

> **同一个账号同时只能有一个任务在跑，且一次只刷一门课** —— 这是程序里写死的规则，不用配。

## 第 12 章 安全建议

1. **`data/` 目录绝不能外传**：里面有学习通**明文账号密码**、数据库、登录密钥。
   （仓库的 `.gitignore` 已经排除它，别手动加回去）

## 第 13 章 完整代码

### 13.1 Dockerfile

```dockerfile
FROM python:3.13-slim

WORKDIR /app

# 换用阿里云 Debian 镜像源（国内加速，避免卡在 deb.debian.org）
RUN set -eux; \
    if [ -f /etc/apt/sources.list.d/debian.sources ]; then \
        sed -i 's|deb.debian.org|mirrors.aliyun.com|g; s|security.debian.org|mirrors.aliyun.com|g' /etc/apt/sources.list.d/debian.sources; \
    fi; \
    if [ -f /etc/apt/sources.list ]; then \
        sed -i 's|deb.debian.org|mirrors.aliyun.com|g; s|security.debian.org|mirrors.aliyun.com|g' /etc/apt/sources.list; \
    fi

# 系统依赖（ddddocr / onnxruntime 运行所需）
RUN apt-get update && apt-get install -y --no-install-recommends \
    libglib2.0-0 libgl1 libgomp1 \
    && rm -rf /var/lib/apt/lists/*

# 先复制依赖清单，利用 Docker 层缓存加速后续构建
COPY requirements.txt /app/requirements.txt
RUN pip install --no-cache-dir -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple

# 复制项目代码
COPY . /app

# 数据目录（数据库、任务配置、日志）—— 通过卷持久化
RUN mkdir -p /app/data/configs /app/data/logs

ENV PYTHONUNBUFFERED=1
ENV PYTHONIOENCODING=utf-8
ENV PORT=5000
ENV HOST=0.0.0.0
ENV CHAOXING_DB=/app/data/chaoxing.db
# 【重要】Cookie 必须落在共享卷内，否则容器重建后登录态丢失
ENV CHAOXING_COOKIES=/app/data/cookies.txt

EXPOSE 5000

# 启动 Web 控制面板
# 注意：必须用 CMD 而不是 ENTRYPOINT，
# 否则 docker-compose 里 worker 服务的 command 会被当成参数追加，
# 导致 worker 容器也去跑 web_panel.py
CMD ["python3", "web_panel.py"]
```

### 13.2 docker-compose.yml（可选，本教程用 `docker run` 更稳）

```yaml
# 兼容旧版 docker-compose（v1）保留 version 字段；新版会提示 obsolete 警告，可忽略
version: "3.8"

services:
  # ---------- Web 控制面板 ----------
  chaoxing-web:
    build: .
    image: chaoxing-web:v14
    container_name: chaoxing-web
    command: ["python3", "web_panel.py"]
    ports:
      - "5000:5000"
    volumes:
      # ★ 关键：数据持久化目录（数据库 / 任务配置 / 日志）
      - ./data:/app/data
    environment:
      - PORT=5000
      - HOST=0.0.0.0
      - PYTHONUNBUFFERED=1
      - PYTHONIOENCODING=utf-8
      - CHAOXING_DB=/app/data/chaoxing.db
    restart: unless-stopped

  # ---------- 任务 Worker（独立进程，互不影响） ----------
  chaoxing-worker:
    build: .
    image: chaoxing-web:v14
    container_name: chaoxing-worker
    command: ["python3", "worker.py"]
    depends_on:
      - chaoxing-web
    volumes:
      - ./data:/app/data
    environment:
      - PYTHONUNBUFFERED=1
      - PYTHONIOENCODING=utf-8
      - CHAOXING_DB=/app/data/chaoxing.db
      # 服务器重启后自动续跑被中断的任务
      - AUTO_RESUME=true
      - MAX_CONCURRENT=5
    restart: unless-stopped
```

> **为什么不推荐 docker-compose？**
> 部分环境里 `docker-compose`（v1，带横杠）和新版 Docker（25+）不兼容，会在重建容器时报
> `KeyError: 'ContainerConfig'`。用本教程的 `docker run` 两条命令最省心；也确实想用 compose 的话，
> 建议先装 compose v2 插件（`apt install docker-compose-v2` 或 `docker-compose-plugin`）。

### 13.4 想再多加并发？加一个 worker 容器即可

```bash
docker run -d --name chaoxing-worker-2 -v /opt/chaoxing/data:/app/data -e AUTO_RESUME=true -e MAX_CONCURRENT=5 --restart unless-stopped chaoxing-web:v14 python3 worker.py
```

> **总能同时刷课的人数 = 所有 worker 容器的 `MAX_CONCURRENT` 之和**。
> 比如 1 个 worker 设 5 → 5 个；再加一个设 5 → 共 10 个。注意总内存（每个任务约 100~150MB）。
